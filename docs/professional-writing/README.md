# Novel Studio 2.11 · 专业创作流程

本轮在既有规划、文学评审、Context Builder、TaskManager、AI Provider 与修订服务上扩展；不新增知识库、编辑器或常驻 Agent。

## 怎样使用

1. **剧情看板 → 剧情矩阵**：新建主线、支线、人物成长或关系线，选择章节和已有场景，保存关联。横向每页最多 24 章，可跨卷查看。现有剧情 State 与人物弧以只读投影显示。长间隔只作规划提示。
2. **场景 → 正文 → 指挥台**：点击场景检查目标、阻力、行动、转折和结果；可用原有规划服务编辑。已写章节需额外确认修改规划。进入正文后，先核对并批准 Writer 安全参考，再创建指挥任务。场景与情绪变化是计划，不是正式事实。
3. **人物成长**：记录目标、信念、关系、决定、情绪的阶段。默认是计划；正文观察必须绑定同章当前原句和版本，仍不能代替 State Commit。
4. **文学评审 → 小说质量分析**：按需运行本地统计，查看句长、段长、引号文字占比、重复词/原样表达/句首、人物名称提及与显式场景长度；点击定位原文。可选最多 20 份正文做趋势对比，或比较同一正文修改前后的统计快照。
5. **文学评审 → 虚拟读者**：选择当前章，按需追加连续章节，每章一个版本，最多 8 章/100000 字符。选择普通、悬疑、人物、节奏或文学编辑立场，填写自定义关注点和模型。只发送指定正文与定位，不读取 Canon、人物秘密、未来大纲或历史报告。反馈属于 AI 主观模拟，不是真实调查。经过原文定位的反馈可进入既有修订待办和 Diff。
6. **正文 → 本次写作参考 → 上下文调试器**：查看实际 Writer 包、资料来源、排除/固定/预算原因、故事时间与已提交截止。预算按 JSON 字符，Token 只显示宽泛估计区间。确认和每次调用均重验资料指纹；旧包不会继续静默使用。秘密不会逐条列入排除清单造成二次泄漏。
7. **正文 → 写后事实**：原文提取、逐项分类为明确叙述/主张/认知/推断/待确认，再通过原有语义 Final Check、Memory Keeper、Proposed State Diff 校验和单独作者 State Commit。接受观察不自动改事实。倒叙按带时区的故事时间与知识取得凭证过滤；缺少历史数据保持未知。

指挥台仍支持快速/导演/深度、流式输出、真实中断、后续暂停、局部保留重写、费用/调用上限与历史检查点。API 不能修改正在生成的内容时，停止当前请求并保存有效部分，再发出作者新要求。执行模型必须是用户实际选择且已配置的 Provider；不会自动跨服务商回退。没有 DeepSeek 配置时不会伪称它执行成功。

## 统计边界

- jieba 0.42.1（MIT）仅在本地分析时初始化；精确模式、HMM 关闭，不修改作者词典或小说。
- 中文终止标点和换行用于分句；句子片段保留。引号统计可能含引文、内心独白；不猜说话人。
- 没有显式分隔符时不猜语义场景数量。人物提及不等于实际出场，同名保持歧义。
- 表达重复只计算原样重复；可能是有意修辞，不自动修改。没有英语阅读难度公式或综合文学分。
- 单章上限 100000 字符；批次合计 300000。分布明细最多 1000 项，界面段落预览最多 120，重复位置有限展示；总量不截断。
- 保存的报告与统计来自项目既有 reviews/literary；矩阵关联使用 metadata/studio 的现有版本化偏好，不构成另一个剧情数据库。

## 采用的成熟产品经验

- [Novelcrafter Matrix](https://www.novelcrafter.com/help/docs/plan/planning-with-the-matrix)：用另一视图检查同一组场景资料，避免另造大纲。
- [Plottr Timeline](https://docs.plottr.com/article/54-timeline-overview)：剧情线、人物弧与章节/场景交叉查看。
- [Scrivener](https://www.literatureandlatte.com/scrivener/overview)：概要卡和正文保持联动。
- [ProWritingAid reports](https://prowritingaid.com/features/writing-reports)、[AutoCrit](https://www.autocrit.com/)：以句长、重复、对白等可量化现象定位审读范围；中文方法单独处理。
- [Sudowrite Feedback](https://feedback.sudowrite.com/en/help/articles/5619921-feedback)：反馈应指向原文并允许自定义关注点。
- [jieba 官方仓库](https://github.com/fxsjy/jieba)：成熟中文切分，不新增 NLP 大框架。

Fictionary 与 NovelAI 的部分官方入口本次无法读取，未据此宣称已经核实它们的具体新功能。产品参考只用于交互决策，没有复制其实现或声称性能等同。

新增界面完整提供简体中文/英语；其余语言通过现有 i18next 明确回退，未冒充新增翻译完成。角色资源和语音沿用现有设置；本轮不改善模型美术或物理输入法/DPI 的既有验收范围。

事实候选默认最多 20 条，可选择 5–60；优先重要变化，并明确不是穷尽式事实清单。场景可采用独立 POV；从矩阵进入会清除上次手选 POV，让作者重新核对。场景与章节时间模式不一致且未给出明确故事时间时，保守排除历史 State/知识/前文；不会按当前章节号补造倒叙时刻。

统计口径 zh-local-2 与正文编辑器一致，排除开头的章标题，并保留原始行号与 UTF-16 定位。显式场景分隔线不计为独立场景；旧口径快照保留，但不同口径不能作前后差值比较。
