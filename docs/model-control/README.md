# Novel Studio 2.21.3 · Model Control and MCP Preview

## 选择具体模型

在软件助手或写作功能顶部的“本轮具体模型”中选择模型。第一次使用 Codex，可点“读取 Codex 模型目录”；该动作不提交生成请求，不需要另配普通 API Key。目录保存在本机应用数据中，后续打开直接显示已有目录，不在启动时连接所有服务。

“Codex 登录默认”继续兼容旧设置。选择具体 ID 后，本次请求使用该 ID；思考强度只显示返回目录中支持的档位。模型目录不是账户权限证明，实际请求可能返回权限或配额错误，不自动换成另一家服务。

设置 → 模型分配，可以保存全局默认、作品默认及任务型号。文件与复杂工作流只能选择 Codex。普通 API 使用已配置服务商的具体 Model ID，服务未提供模型列表时仍可手动配置。

## 让 Codex 操作软件

打开软件助手，选 Codex 具体模型，输入明确任务，例如“请查询当前作品的章节列表，打开第二章，然后查找其中的人物资料”。Codex 通过本机 MCP 调用既有 Action Registry；应用仍执行项目权限、固定确认及真实界面回执检查。

助手的受控能力目录展示当前可用操作。它能导航、查询和请求草稿或既有工作流，不提供任意 Shell、SQL 或明文密钥读取。修改 Final/Canon/State 仍须原有审核流程，模型回复不代表已经执行。

已经明确且能精确识别的本地指令仍走已有快捷 Action，界面标明“未经过 AI”。多步骤自然语言操作交给 Codex，逐项操作状态以真实回执为准。

本次已排队请求使用参数快照。修改控件用于下一轮，不改变运行中的任务。停止按钮只停止对应任务。

## 连续操作

同一作品、角色、模型、参数、上下文及权限完全一致，且上一回合结束、没有待确认操作时，可在短时窗口内复用已有受限 Codex 连接。切换作品、角色、模型、上下文范围或权限会建立新连接。取消和过期会话不会复用。

## 数据与发行边界

不修改全局 Codex 登录或配置，不增加运行依赖。测试使用独立演示项目；发行包不包含真实作品、API Key、用户登录或私人角色模型。软件继续标记 Preview，外部服务可用性以实际请求为准。

桌面启动器使用标准 HTTP 连接检查自身回环服务，不依赖远端 AI，不修改系统代理或全局网络设置。

Windows 包显式包含动态启动的 assistant MCP 服务模块；EXE 的 --assistant-mcp 使用同一 Action Registry，不需要用户单独启动 Python。

## 技术依据

- [Codex App Server：model/list 与 Thread](https://learn.chatgpt.com/docs/app-server)：模型目录及思考档位以实际返回为准；具体型号传给 Thread 和 Turn。
- [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)：本机 stdio、工具白名单及独立启动/工具超时。

目录读取与连接探测不等于模型推理成功；真正的软件操作需要 Codex 工具调用、Action 执行与前端回执三个环节都完成。

若开发环境使用附带额外 CA 拒绝策略的 CPython 运行时，打包会原样携带对应的公开信任策略文件；不关闭 TLS 校验、不放宽证书策略。该文件不是用户凭据。
