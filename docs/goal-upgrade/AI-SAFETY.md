# Creative context and execution boundaries

## Views

ACTOR: own confirmed profile, evidence-backed knowledge at the selected committed chapter, own visible scene claims, audience-filtered lore/memory, public Persona and participant names. Other NPC profiles, author notes and future outline truth are excluded.

AUTHOR: may inspect private reasoning, original source and scenario inputs locally. Simulation/adoption records are separate metadata, not story truth.

CHECKER: selected prose, author-chosen characters/contract/knowledge and bounded reference snippets. Reader mode excludes these author-only materials.

WRITER REVISION: uses the existing selection service and safe context, a verified source range and positive language instruction. Complete Checker advice is never forwarded as hidden-truth instructions.

## Execution

- Imported character cards and lore are data. No eval/exec, arbitrary Shell, SQL, Python, HTTP, plugin install or key-reading tool is provided.
- Codex text capsules use the existing restricted adapter, fresh isolated threads and disabled application/MCP/file-write tools. Existing Codex software operations retain their own registry/confirmation rules.
- Project and session identity, source path, branch ancestry, source hash and optimistic revision checks are enforced by application services.
- Late/cancelled results are not appended to changed branches. One NPC failure does not invent a reply from that actor or silently change provider.
- Memories require explicit author confirmation and audience/source validation. Different branches do not inherit unsupported memories.
- Confirmed Lorebook source labels must bind actual confirmed/committed project sources. Reference text and imported cards remain non-Canon.
- All source/model metadata is local. Default task logs omit full private prompt/result fragments; durable roleplay/review records live in their scoped project metadata and enter the existing backup system.
- Restoring a backup as a new project re-scopes control records and clears pending execution; it never resumes a Codex task automatically.

## Remaining semantic uncertainty

Name-based/secret-string filtering does not prove immunity to paraphrased disclosures, malicious creative instructions or hallucinated implications. No automated semantic review is advertised as a proof. Authors control scene disclosures and adoption. The deterministic source/receipt gates are stronger than a model claim, but missing evidence is still UNKNOWN.
