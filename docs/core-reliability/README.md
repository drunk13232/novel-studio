# Novel Studio 2.11.2 Core Reliability Preview

本版沿用已有写作、AI、实验与备份服务，只修复上一轮审计确认的问题。2.11.1 发行版保留供回退。项目最终开源许可仍由作者决定。

## State 候选

正文工作台 → 写作协助 → State 闭环。先保存当前章正文，再查看候选。列表只查询该作品、该章、该正文路径，按稳定 ID 排序；可筛选全部、尚未提交、已提交，并翻页。列表发生变化时需刷新，避免跨页遗漏。历史审稿与验证文件不占候选页数。

元数据缓存只用于列表加速，不是新的 State 权威。提交仍重新读取正文、Final、Proposed Diff、基线、语义审查及验证回执，作者独立确认后才执行原 State Commit。

## 人工验收

世界逻辑实验室 → 执行结果。人工规则显示“等待作者人工验收”。填写判断依据，再点击“作者确认通过”或“作者确认不通过”。自动数学结果与人工判断分开显示。所有必要条件通过后整体才能 PASS；人工通过不能覆盖数学失败。

作者记录绑定报告、输入版本、验收指纹、规则指纹并检查审核记录版本。实验或规则变化后旧判断不再生效，新版本需重新运行和审核。原求解报告不被改写，历史判断可追溯。AI 工具不提供人工批准接口。

## 备份与恢复

数据与备份 → 备份与恢复。勾选“包含本作品的助手聊天、角色会话和创作任务历史”以备份私人讨论；取消后不会加入当前会话、对应检查点和旧任务日志。作品正文、设定与其他原有备份内容仍保留。

助手会话按作品、角色、模型分别保存。恢复为新作品时重绑作用域，保留历史记录、项目模型偏好与角色权限；等待确认和运行中任务变为中断，不会自动请求 AI。新电脑没有原 Provider 时会保留历史模型标识供阅读，不会静默改用 Codex 或另一服务商。需要重新配置服务商及密钥才能继续调用该模型。

全局 AI/角色设置默认不覆盖；只有原有“恢复个人设置”选项明确开启时，才恢复对应全局非敏感设置。API Key、Codex 登录、Cubism Core 和私人角色模型不进入助手备份。旧版备份缺少新增会话条目时仍可恢复。

旧格式会话是散列文件名，仅从作用域登记、当前配置及本作品用量记录中确认其所属模型；无法证实归属的孤立旧文件不会猜测导入。助手会话单次备份上限 23 MiB，超限会明确报错，可先单独保存讨论或关闭包含私人历史选项。

## Provider 测试

设置 → AI 接口 → 编辑服务商／模型 → 保存 → 勾选费用提示 → 最小生成测试。按 Chat Completions 或 Responses 协议测试；Chat 未知的可选 Token 参数不发送，已确认的 max_tokens 或 max_completion_tokens 映射照常使用。未知映射下服务商可能按默认输出上限计费。

结果区分本地配置、参数映射、参数不支持、401 认证、403 权限、404 模型或接口、429 配额、服务不可达、超时、返回格式与实际成功。超时不自动重试，也不切换服务商。列表接口失败不代表最小生成一定失败。TEXT_GENERATION_OK 只确认文本调用，不认证 Agent 或 Skills 能力。

## 其他修复及验证边界

受限表达式支持 -8 至 8 的有符号整数字面量幂：2**-1=0.5，-2**2=-4，(-2)**2=4。没有 eval、exec 或不可信 parse_expr；动态指数、过大指数和零的负幂仍拒绝。

Monaco 0.57.0 保持不变，仅覆盖其 DOMPurify 依赖到官方 3.4.16。依据：[官方发布说明](https://github.com/cure53/DOMPurify/releases/tag/3.4.16)、[安全公告一](https://github.com/advisories/GHSA-p98j-92pf-mc4p)、[安全公告二](https://github.com/advisories/GHSA-6688-9rhm-gjv2)。不宣称本产品已被利用。

检查限定在受影响模块。LOCAL、MOCK HTTP 和真实 Windows WebView2 UI 证据分开记录。没有收费第三方 API 验收授权，不测试真实 DeepSeek；原生中文输入法候选操作和全部系统 DPI 仍不属于本次认证范围。新增文案优先中英，其他语言沿用明确回退。
