# Novel Studio 2.11.1：创作指挥与状态闭环

此版本继续使用现有编辑器、AI Provider、任务管理、修订、世界实验室和 YAML State。真实作品是否采用正文、事实与状态变化，始终由作者分别决定。软件属于 Preview；外部模型服务和文学质量需按实际配置判断。

## 从写作目标到正文

1. 打开章节并保存。在「本次写作参考」选择 POV、场景、时间与有限资料，预览实际 Writer 包，再确认本次发送范围。秘密不会因一句“不要泄露”就取得 Writer 权限。
2. 打开「AI 创作指挥台」。指挥模型负责规划，执行模型负责正文；两者从现有 AI 设置中选择。使用“按任务设置”时，在创建或保存时解析并固定实际模型，不在请求失败后跨服务商回退。
3. 快速模式直接写候选；导演模式规划一场；深度模式最多四步。查看已加载方法的来源、SHA-256、任务书中的方法应用和待作者决定事项，再确认执行。
4. 生成时可暂停后续调度，或取消当前请求。取消保留已经收到的正文，不保证上游未计费，也不是远端无损暂停。
5. 要保留前文，在候选文本里将光标放在保留末尾，填写新的要求，选择「保留到光标，重写后文」。程序先取消请求，再保存精确前缀；被舍弃的后文留在旧检查点。也可以停止后由作者接管，或选中一段单独重写。
6. 「进入现有 Diff 比较」只创建候选。关闭或拒绝不改变原文；确认后才通过既有版本与冲突保护保存。源正文已经变化时，需要重新核对，不能将旧候选静默套入新版本。

Codex 使用原有登录。普通兼容 API 没有 Skills、文件和 State 的执行权限。DeepSeek 等远端执行者需要用户自行配置并授权；未配置时不会伪造调用。调用量、价格或首段时间未返回时显示 UNKNOWN。

## 世界实验结果返回写作

指挥台右侧的「用世界实验室分析当前场景」进入已有的人物分析与规则实验。保存需要的输入及验收版本，运行实际求解器后，明确选取一个人物方案或实验报告带回。

结果经现有灵感记录保存为有来源的创作素材，标识为假设、模拟对话或条件性计算，不是 Canon。检查新增 Writer 参考并重新批准后，可回到原指挥任务，保存新参考，再继续。原文发生变化后，另建针对新版本的任务。确定性数学结果不等于社会行为预测，未选择的推演不会自动进入 Writer 或 State。

## 定稿、事实与正式状态

正文旁的「章节定稿与状态闭环」展示现有门禁：

1. 语义 Final Check：使用现有 Codex / 项目 Skill，核对当前精确版本的合同、连续性、人物、场景剧情、语言。仅有机械检查不能生成有效语义 Final。正文或审查报告变化后，旧 witness 失效。
2. 写后事实：提取有限数量的原文候选，逐项接受、编辑、拒绝或暂缓。角色主张、信念、推测和待确认信息分别标识。作者接受候选不等于提交 State。
3. Memory Keeper：先明确填写带时区的本章结束状态时间。软件不自动将大纲时间转为事实；这个时间是作者指定的保守状态锚点，不声称所有动作同时发生。回忆中的具体事件时间仍需另行证据。

   确认的候选可经已有入口交给 Memory Keeper；也可在语义 Final 通过后直接启动原有 Memory 任务。只生成 Memory / Proposed，不改正式 State。
4. 选择本章 Proposed Diff，查看每项原文证据、提交前和提交后内容。必要的语义 Diff 审查完成后，现有脚本再次验证 Schema、引用、知识回执、正文与状态基线。
5. 勾选独立授权并点击「作者 State Commit」。这一步在应用中调用原有原子提交与回滚机制，不需要模型再规划操作。确认绑定精确 proposal 哈希与基线；重复同一有效提交返回已有结果。
6. 下一章重新生成并批准 Writer Context。旧包因 State 变化失效。人物知识使用获得章节、时间与来源回执；关系、物品及伤势使用已提交、在当前 POV 和故事时间可见的 Writer views。缺少历史视图时保持未知，不把最新状态倒推为过去事实。

状态闭环页可以刷新并重开现有任务记录；重启不会自行继续生成或提交。失败时保留候选并显示原因，先解决问题再重试。State Commit 与 Git commit 无关。

## 性能与恢复边界

专业方法文本按文件版本缓存，选定方法才进入规划。执行阶段使用批准的方法约束与 Writer 包，不再次请求规划或探测其他服务商。任务记录保存各次实际模型、调用时长与首段时间；网络、服务端排队和推理仍可能较慢，缓存不保证固定加速幅度。

上下文、计划、草稿、干预和有限版本检查点存于当前作品已有 metadata，正文仍走原文件与版本机制。不要将私人 metadata、实际小说、API 配置密钥、运行记录或角色资源加入公开发行。

## 受限 Windows 环境

本版的状态闭环通过现有纯文本 Codex Adapter 返回结构化审查和 Memory 数据，由应用调用原有状态函数写入报告、候选和回执。它不依赖模型启动 Shell，也不增加模型的文件权限。原始文件型 Codex 工程任务仍是独立能力；若本机 Windows 沙盒拒绝启动，软件会保留实际错误，不能仅凭模型回合结束就认定文件任务成功。

正式 State Commit 后，当前章按照既有已提交章节保护立即刷新为只读；后续修改使用独立修订稿，下一章重新建立 Writer Context。失败的 Memory / Proposed 保留，作者补全参数或修订候选须创建并审核新版本，不覆盖失败证据。
