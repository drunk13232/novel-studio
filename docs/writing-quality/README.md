# 写作校审（2.10.3 定向更新）

正文工具栏的「写作校审」打开原文学评审中心。创作模式、章节状态、自动保存、Writer Knowledge Isolation 和 State Commit 规则保持原有权威。校审不会自动将章节标为 Final。

## 使用

1. 保存当前草稿后打开「写作校审」，选择实际章节版本。无需逐项走完所有审核。
2. 「快速校对」可选离线标点与排版，或当前已配置模型的错字与病句检查。离线不包含中文语义纠错模型。
3. 「深度逻辑审核」核对当前章。只在主动勾选后加入当前作品合同、所选人物的知识记录。当前知识不能倒推历史。
4. 「全书一致性 · 检索核对」输入人物、物品或其他关键词，也可以指定相关章节。使用原有 FTS 索引筛选候选，再读取实际原文；一次最多十二份相关章节、每份最多 7000 字符。没有覆盖的内容明确标为未检查，不能当作全书通过。
5. 点击「定位原文」。文字问题可以「查看最小修改 Diff」，接受、自行编辑、拒绝、忽略或暂缓。可选查看其他修改方案。任何状态操作都不会偷偷改写正文。
6. 接受候选复用既有 StudioTools：校验文件哈希、版本、UTF-16 选区，保存前创建历史检查点。Final 另存独立 manual 修订稿。旧坐标或关联证据失效会拒绝替换。单次接受后其余旧建议需要重新核验；不会盲目批量接受。
7. 术语词典自动复用人物及设定名称；自定义词每行一个。忽略可记住在本报告、本文件或当前作品范围内。不同作品不共享词典和忽略项。已接受状态从真实候选回执恢复。
8. 「十二维文学评审」保留原十二种主观维度与模型对比。相同模型重复调用不等于独立验证。逻辑报告可送入现有世界逻辑实验室，由作者确认形式化后执行求解；文字校审不伪造求解结果。

## 实际边界

- AI 报告属于作者/Checker 视图，不直接送给 Writer；逐项文字候选不启动新 Agent。
- 本轮未捆绑 pycorrector、LanguageTool、模型权重、Java 服务或 Promptfoo 运行服务。
- 不按键触发 AI 或强制红色波浪线；仅显式检查、显式定位。Diff 修改按钮在中文 composition 期间禁用。
- 章节实际时间、故意误导、人物说谎及特殊世界规则仍需作者判断。文本引用可核验，并不自动证明其推论正确。
- 报告保存于当前作品 reviews/literary，词典及忽略为可恢复的同目录元数据；不是 Canon。原数据中心按项目备份规则包含这些文件。
- 新界面文案覆盖简体中文与英语，其余语言使用既有明确回退。没有把英语复制为已完成翻译。

## 检查与开发

定向测试：`python -m pytest web/backend/tests/test_writing_quality.py web/backend/tests/test_creative_boundaries.py -q`，仅使用演示模板的临时副本。标注样本为 `web/backend/tests/fixtures/writing-quality-gold.json`，包含故意错误与不应误报的文本。不得用其小样本成绩宣称出版级准确率。

新 API 均在原 `/api/projects/{p}/literary-review`：`POST /run` 新增 proofread、chapter_logic、cross_chapter，`GET/PUT /dictionary`，`POST /reports/{id}/replacement`。报告、任务、Diff、决定和文学对比继续使用原接口与权限，不暴露任意文件、Shell 或 SQL 工具。
