# Phase 6: 章节细纲 & Beat Sheet

> **阶段编号**: Phase 6 / 10
> **执行角色**: 🎭 剧情编剧
> **触发条件**: Phase 5 完成（至少当前卷的分卷规划已完成）
> **阶段目标**: 为每一章生成精确的Beat Sheet（节拍表），细化到每个场景的情节点
> **输出产物**: `outlines/chapters/ch-XXX.md` 章节细纲（每次批量生成3-5章）

---

## 一、阶段概述

章节细纲是正文生成前的最后一道规划。它把卷级大纲中的"概要描述"转化为**具体的场景序列**，每个场景都有明确的情感目标和信息量控制。

**核心理念**：好的细纲 = 好的正文的一半。细纲越清晰，正文写作越高效、越不容易跑偏。

**批量生成策略**：每次规划3-5章的细纲，而非一次规划全部。这样可以根据前面章节的实际写作情况，动态调整后续细纲。

## 二、Beat Sheet 系统

### 2.1 什么是Beat Sheet？

Beat Sheet（节拍表）是好莱坞编剧常用的工具，将每一章分解为若干个"Beat"（节拍），每个Beat都有明确的功能和情感方向。

### 2.2 标准章节Beat结构

一章（2000-4000字）通常包含 4-6 个 Beat：

```
【章节Beat结构】

┌─────────────────────────────────────────────┐
│ Opening Beat（开场节拍）  约300-500字        │
│ 功能：承接上章 + 建立本章基调                 │
│ 类型：场景描写 / 角色状态 / 悬念延续          │
├─────────────────────────────────────────────┤
│ Progress Beat 1（推进节拍1）  约500-800字     │
│ 功能：推进情节 / 揭示信息 / 制造冲突          │
│ 类型：对话 / 行动 / 发现                      │
├─────────────────────────────────────────────┤
│ Progress Beat 2（推进节拍2）  约500-800字     │
│ 功能：深化冲突 / 转折 / 角色决策              │
│ 类型：对抗 / 抉择 / 意外                      │
├─────────────────────────────────────────────┤
│ Climax Beat（高潮节拍）  约500-1000字         │
│ 功能：本章最强烈的情感/事件高点               │
│ 类型：战斗高潮 / 真相揭露 / 情感爆发          │
├─────────────────────────────────────────────┤
│ Closing Beat（收尾节拍）  约300-500字         │
│ 功能：收束本章 + 为下章设钩                   │
│ 类型：结果展示 / 新悬念 / 情感余韵            │
└─────────────────────────────────────────────┘
```

### 2.3 Beat 类型速查

| Beat类型 | 情感方向 | 适用场景 | 字数占比 |
|---------|---------|---------|---------|
| 场景设定 Beat | 中性 | 新场景转换、环境描写 | 10-15% |
| 对话 Beat | 灵活 | 信息传递、角色互动 | 20-30% |
| 行动 Beat | 上升 | 主角采取行动、推进目标 | 15-25% |
| 冲突 Beat | 紧张 | 对抗、争论、危机 | 15-25% |
| 内心 Beat | 深沉 | 角色反思、决策、情感 | 10-15% |
| 反转 Beat | 急转 | 意外事件、真相揭露 | 5-10% |
| 爽点 Beat | 飙升 | 打脸、突破、逆袭 | 10-20% |
| 钩子 Beat | 悬停 | 章末悬念、未解之谜 | 5-10% |

## 三、完整章节细纲模板

```markdown
# 章节细纲：第XX章 - [章节标题]

## 元信息
- **所属卷**：第X卷
- **章节编号**：第XX章（全书）/ 第X章（本卷）
- **字数目标**：约3000字
- **节奏定位**：⚡紧张 / 🔥推进 / 🌊缓冲
- **情感基调**：[燃/虐/甜/悬/日常]
- **本章主要POV**：[视角角色]

## 场景时间线
- **时间**：故事内第X天 / X月X日 / 某时辰
- **地点**：[具体地点]
- **天气/环境**：[如有影响]

## Beat Sheet

### Beat 1：开场（约400字）
- **类型**：场景设定 + 承接
- **内容**：[具体描述这个Beat要写什么]
- **情感方向**：[↗上升 / →平稳 / ↘下降]
- **关键信息**：[这个Beat需要传递的信息]
- **写作提示**：[如何写好这个Beat的建议]

### Beat 2：推进A（约700字）
- **类型**：对话 Beat
- **参与角色**：主角 + [角色名]
- **对话目的**：[通过对话揭示/推进什么]
- **潜台词**：[角色真正想表达但没说出口的]
- **情感方向**：↗
- **注意事项**：
  - [角色A的说话风格提醒]
  - [不要提及的信息（此时角色还不知道）]

### Beat 3：推进B（约700字）
- **类型**：行动 Beat
- **内容**：[主角采取的行动]
- **障碍**：[遇到的阻碍]
- **情感方向**：↗↗
- **战力参考**：[如涉及战斗，参照rules.md的限制]

### Beat 4：高潮（约800字）
- **类型**：爽点 Beat / 冲突 Beat / 反转 Beat
- **内容**：[本章最精彩的部分]
- **爽点/锚点类型**：[打脸/突破/逆袭/真相/感情]
- **情感方向**：⬆ 飙升
- **读者期待的感受**：["太爽了" / "卧槽" / "泪目"]

### Beat 5：收尾（约400字）
- **类型**：钩子 Beat
- **内容**：[收束本章 + 埋下钩子]
- **章末钩子**：[具体的悬念/期待]
- **钩子类型**：[悬念型/预告型/反转型/情感型]
- **情感方向**：⤴ 悬停

## 交叉引用检查
- [ ] 涉及设定：[引用rules.md的第X条]
- [ ] 涉及角色：[引用角色卡，检查一致性]
- [ ] 涉及伏笔：[本章是否回收/埋设伏笔]
- [ ] 涉及时间线：[与前后章的时间是否连贯]
- [ ] 前章承接：[上一章的结尾是什么状态]
```

## 四、情感曲线（章节级）

### 4.1 单章情感曲线设计

每一章的情感变化也应该有设计，不是平铺直叙：

```
情感强度（单章）

高  │        ★ ← 章节高潮
    │       ╱ ╲
    │      ╱   ╲
    │     ╱     ╲
    │    ╱       ╲→ ？ ← 钩子（悬停）
    │   ╱
    │  ╱
低  │ ╱ ← 开场（承接上章情感）
    └──────────────────── 阅读进度
     开场   推进   高潮  收尾
```

### 4.2 不同类型章节的情感曲线

**战斗章**：
```
低→中（铺垫）→高（交手）→更高（危机）→最高（逆转/胜利）→中（收束）
```

**日常章**：
```
中（日常）→中高（趣事/互动）→中（平稳）→中高（温馨/搞笑）→中低（平和结束）+ 暗线伏笔
```

**揭秘章**：
```
中（疑惑）→中高（调查）→高（接近真相）→最高（真相揭露！）→中低（消化/新疑问）
```

**虐心章**：
```
中高（温馨铺垫）→中（隐约不安）→低（噩耗/失去）→最低（情感最深处）→微升（希望/决心）
```

## 五、爽点 & 情感锚点设计

### 5.1 爽点清单（分类参考）

```markdown
## 📈 爽点类型库

### 逆袭爽
- 被看不起的主角展示实力
- 预测失败的事情反而成功
- 从最弱变最强（阶段性）

### 打脸爽
- 自大的对手被主角碾压
- 嘲笑主角的人被现实打脸
- 做出正确预判而别人都错了

### 突破爽
- 境界突破 + 实力暴涨
- 领悟新技能/功法
- 获得珍贵宝物/传承

### 真相爽
- 揭露反派阴谋
- 解开长期悬念
- 身世之谜揭晓

### 情感爽
- 虐后甜（分离后重逢）
- 认可（被重要的人认可）
- 守护成功（保护了在乎的人）
```

### 5.2 情感锚点设计

情感锚点是让读者产生强烈情感共鸣的场景。它不一定是"爽"，但一定是"触动人心"。

```markdown
## 🎯 情感锚点类型

### 燃点（热血沸腾）
- 绝境中的不屈宣言
- 为同伴挺身而出
- "即使知道会输，也要站着战斗"

### 泪点（感动/悲伤）
- 角色的牺牲
- 迟来的理解/道歉
- 物是人非的重逢

### 甜点（温馨/心动）
- 不经意的关心
- 互相理解的瞬间
- 一个恰到好处的笑容

### 震撼点（认知颠覆）
- "原来一直是他！"
- 世界观的翻转
- 预料之外但情理之中的真相
```

## 六、章末钩子设计

### 6.1 钩子类型与使用

| 钩子类型 | 效果 | 示例 | 使用频率 |
|---------|------|------|---------|
| 悬念型 | "然后呢？？" | 门被推开，站在外面的人竟然是—— | 最常用 |
| 反转型 | "什么！" | 他以为自己赢了，却不知道真正的敌人一直在身边 | 重要章节 |
| 预告型 | "要来了！" | 远处的天空中，渡劫的雷云正在聚集 | 弧段前 |
| 情感型 | "啊啊啊啊" | 她终于说出了那句一直没说出口的话 | 感情线 |
| 危机型 | "不好了" | 突然间，他感到一股令人窒息的压力从天而降 | 战斗前 |

### 6.2 钩子设计原则

1. **每章必须有钩子**——这是网文的铁律
2. **不要假钩子**——吊起的胃口必须在后续兑现
3. **钩子要有层次**——不能每章都是"这时，一个黑影出现了"
4. **钩子与正文匹配**——搞笑章用轻松钩子，严肃章用沉重钩子

## 七、批量规划工作流

### 7.1 每次规划3-5章

```
工作流：
1. 确认当前进度：前面写到了哪里，有什么未完成的线索
2. 对照卷级大纲：当前应该推进到哪个阶段
3. 设计3-5章的Beat Sheet
4. 检查爽点分布：这3-5章中至少有1个明确爽点
5. 检查节奏平衡：不要连续紧张或连续缓冲
6. 交叉引用检查：设定、角色、时间线、伏笔
7. 输出细纲文件
```

### 7.2 动态调整机制

细纲不是一成不变的。在实际写作（Phase 7）中，如果发现：
- 某个Beat展开后超出了预计字数 → 调整后续Beat
- 写着写着发现更好的情节走向 → 可以修改后续细纲
- 角色互动产生了意外的化学反应 → 可以加入新的场景

但调整的边界是：**不能偏离卷级大纲的核心任务和关键事件**。

## 八、交叉引用检查清单

每完成一批细纲，必须进行以下检查：

```
【细纲交叉检查】
□ 设定抛出率控制（Info-dump Limiter）：直接设定的说明文字是否低于全章字数的 10%？（务必坚持 Show, Don't Tell）
□ 设定一致性：所有能力使用是否符合 rules.md？
□ 角色一致性：角色的行为是否符合角色卡？
□ 时间线一致性：章节间的时间跨度是否合理？
□ 地理一致性：角色的位置移动是否合理？
□ 信息一致性：角色此时应该知道/不知道什么？
□ 伏笔管理：本批次是否有需要回收的伏笔？
□ 爽点密度：3-5章内是否有至少1个明确爽点？
□ 钩子质量：每章是否有合理的章末钩子？
```
